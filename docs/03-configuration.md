# Настройка Re:HomeProxy под сервер Hiddify

Пошагово: от подписки до работающего обхода блокировок. Всё в LuCI:
**Службы → Re:HomeProxy**.

---

## 1. Убедитесь, что ядро установлено

Откройте **Ядро и службы → Управление ядром**. Там должно быть видно
**hiddify-core** с версией. Если «?» — перезапустите rpcd и войдите заново:

```sh
/etc/init.d/rpcd restart
```

---

## 2. Добавьте подписку Hiddify

**Настройки узлов → Подписки** → добавьте **ссылку подписки**.

Ссылку берёте в панели Hiddify (раздел пользователя → «Подписка» / Subscription).
Обычно это `https://ваш-домен/суб-путь/ТОКЕН`.

Что важно:

- Re:HomeProxy сам запрашивает нужный формат через **User-Agent**. Для клиента
  Hiddify-совместимый формат (sing-box JSON) он получает автоматически. Если
  сервер отдаёт не то — задайте свой User-Agent (например, `Hiddify/2.5.7`).
- Включите **Автообновление** (например, в 02:00), чтобы список узлов не устаревал.
- **Обновлять через прокси** — оставьте выключенным, если только сам хост подписки
  не заблокирован (иначе на старте получится «курица и яйцо»).

Альтернативы (кнопки на вкладке **Узлы**):

- **Импортировать ссылку-конфигурацию** — вставить `vless://`, `vmess://`, `ss://`,
  `trojan://`, `hysteria2://`, `tuic://`, `vpn://` (Amnezia) и др., по одной на строку.
- **Импорт WG (.conf)** — файл WireGuard/AmneziaWG (AmneziaWG требует sing-box-extended).

Из командной строки то же делает `scripts/add-subscription.sh`:

```sh
sh scripts/add-subscription.sh "https://ваш-домен/sub/ТОКЕН" --auto --hour 2
```

После добавления нажмите **Обновить** (или скрипт сам скачает узлы).

---

## 3. Выберите основной узел

**Настройки клиента → Настройки маршрутизации → Основной узел**:

- конкретный узел из подписки, **или**
- **URLTest** — авто-выбор самого быстрого узла из указанного набора, с
  автопереключением при сбое (рекомендуется, если узлов несколько).

Поле **Основной UDP-узел** оставьте «Как основной узел», если не нужно отдельно
гонять QUIC/голос через другой узел.

---

## 4. Режим маршрутизации для РФ

**Настройки клиента → Настройки маршрутизации → Режим маршрутизации** =
**Россия (Обход Блокировок)** (`proxy_banned_ru`).

Логика: **всё идёт напрямую**, через прокси — только то, что вы явно добавите в
**Правила прокси (РФ)**. Это экономит трафик и скорость VPN.

Проверьте связанные опции:

- **DNS-сервер России** — резолвит обычные/российские домены напрямую (Yandex 77.88.8.8).
- **Защищённый DNS-сервер** — резолвит заблокированные домены через прокси по DoH
  (Cloudflare). Это важно, чтобы провайдер не видел запросы.
- **Не проксировать торренты** — включите, если не хотите гнать P2P через VPN.
- **Проксировать звонки** — по желанию (VoIP WhatsApp/Telegram через прокси).
- **Режим прокси** — по умолчанию `Redirect TCP + TProxy UDP` (подходит). Режимы
  TUN требуют `kmod-tun` (мы его ставим).

---

## 5. Включите нужные списки (Правила прокси РФ)

Вкладка **Правила прокси (РФ)**. Маршрут по умолчанию — **Напрямую**, проксируется
только добавленное. Каждое правило = список-источник + узел.

Рекомендованный минимум:

1. **Russia Inside** (1000+ доменов) — базовый набор.
2. **Re:Filter** (60 000+ доменов, 25 000+ IP) — список блокировок Роскомнадзора.

Приоритет применяется автоматически (сначала мелкие сервисные списки, потом
Russia Inside, потом Re:Filter). Списки обновляются на роутере сами.

Для сервисов, которые «тормозят» (YouTube, Discord), вместо VPN-узла можно выбрать
исходящий **ByeDPI** или **Zapret** — обход DPI без расхода трафика VPN
(см. `docs/05-dpi-bypass.md`).

---

## 6. Контроль доступа (какие устройства проксировать)

**Настройки клиента → Контроль доступа**. По умолчанию проксируются все устройства
LAN по общим правилам. При необходимости:

- **Режим проксирования устройств** — «Проксировать только указанные» / «всё кроме указанных».
- **Игровой режим** — для выбранных устройств проксируется только TCP (меньше лаг).
- **Глобальный прокси** — для выбранных устройств весь трафик через прокси.

---

## 7. Сохранить, применить, проверить

Нажмите **Сохранить и применить**, затем:

```sh
/etc/init.d/homeproxy restart
```

Проверка:

1. **Диагностика → Проверка соединения**: на hiddify-core показывается **IP провайдера**
   против **IP прокси** — они должны различаться.
2. **Диагностика → Ядро и система**: ядро установлено и запущено.
3. **Диагностика → Конфигурация**: конфиг валиден.

Быстрая проверка из консоли:

```sh
sh scripts/diagnose.sh
```

или вручную:

```sh
curl -s https://api.ipify.org                                        # прямой IP
curl -s -x socks5h://127.0.0.1:5330 https://api.ipify.org            # IP через прокси
```

Если IP совпадают — трафик не проксируется: проверьте узел, режим маршрутизации и
включённые списки.

---

## 8. Обновление ядра и списков

- **Ядро:** **Ядро и службы → Управление ядром → Установить** (обновит до последнего релиза).
- **Списки РФ и гео-данные:** **Ядро и службы → Управление ресурсами → Проверить обновление**
  (RU-списки обновляются и сами по расписанию).
- **Подписки:** вручную на вкладке «Подписки» или автоматически по cron.
